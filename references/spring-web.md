# Spring Web 与 API

规则编号用于接口 Review；是否拆分对象仍以现有契约和变更风险为准。

## WEB-001 Controller 与应用服务边界

级别：MUST
适用：对外 HTTP 接口和管理接口。

规则：Controller 负责协议适配、鉴权入口和调用应用服务；复杂业务、事务和持久化放在服务层。

正例：Controller 将已校验的 Command 传给应用服务，由服务层完成业务决策。

反例：Controller 直接访问 Mapper，或在 Controller 中编排多步写操作和事务。

例外：极简单的只读内部端点可以保持轻量，但不能绕过必要的权限边界。

## WEB-002 请求与响应对象隔离

级别：MUST
适用：对外请求和响应，尤其是包含持久化字段的接口。

规则：请求使用专用 DTO/Command，响应使用 VO/Response；除非明确是内部接口，不直接暴露 Entity/DO。

正例：将 Entity 映射为只包含允许字段的 Response，并通过 DTO 接收输入。

反例：`return userRepository.findById(id)` 直接把 Entity 序列化给前端。

例外：内部、受控且有稳定契约的接口可以复用类型，但应记录原因。

## WEB-003 输入校验与稳定错误结构

级别：MUST
适用：所有来自 HTTP 请求的参数、路径变量、查询条件和请求体。

规则：使用 Bean Validation 或项目统一校验器；校验失败通过统一异常处理返回稳定错误结构。

正例：在请求 DTO 上声明 `@NotBlank`、`@Positive`，并由统一处理器转换错误码。

反例：只在前端校验，或把校验异常堆栈直接返回客户端。

例外：内部批处理接口也必须校验输入，只是错误报告格式可以按批处理协议调整。

## WEB-004 API 兼容与副作用边界

级别：MUST
适用：新增或修改公开 API、分页、写操作、导出和长任务。

规则：路径、HTTP 方法、状态码和分页语义与现有 API 保持一致；新增字段考虑向后兼容。写操作按业务需要采用幂等键或唯一约束；导出、大文件和长任务不要同步占用请求线程。

正例：新增可选响应字段，长任务返回任务标识并异步查询结果。

反例：改变已有字段含义，或在请求线程中同步生成无界大文件。

例外：版本化 API 或已获客户端迁移计划的破坏性变更必须明确标注兼容窗口。

生成代码时只有在响应契约或校验方式会影响实现时才读取对应的 contract 文件；如果项目已有响应类，应复用它，不要凭空创建新的公共类。

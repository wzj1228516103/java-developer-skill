# 事务、一致性与幂等

规则编号用于事务 Review、回归验证和发布例外记录。

## TX-001 数据库事务边界

级别：MUST
适用：同一数据库内必须原子完成的多步写操作。

规则：事务覆盖必须原子完成的本地写操作并使用匹配的事务管理器；默认 Spring 代理模式下，同类自调用不会触发新的事务语义，类代理不能增强 final 类/方法。运行时异常默认回滚，检查型异常和捕获后正常返回需按契约显式处理。

正例：由外部代理可调用的应用服务方法开启事务，并在事务测试中验证提交和回滚。

反例：在 Controller 拼装事务，或误以为同类 `this.method()` 会触发 `@Transactional`。

例外：框架原生事务 API 或 AspectJ 模式按实际语义判断；单次原子写或普通只读查询无需机械增加事务注解。

## TX-002 事务内禁止不可控外部 IO

级别：BLOCKER
适用：事务方法中的 HTTP/RPC、消息发送、文件操作和长时间等待。

规则：不要在数据库事务中执行不可控的 HTTP/RPC、长时间等待或大批量外部 IO；需要时采用事件、Outbox 或补偿方案。

正例：本地事务只写状态和 Outbox，提交后由可靠消费者调用外部服务。

反例：持有数据库锁调用支付接口，失败时让事务和远程重试互相阻塞。

例外：短时、可控且有严格超时的调用也要基于锁占用和失败恢复评估，不得仅凭“接口很快”放行。

## TX-003 重试与幂等

级别：BLOCKER
适用：支付、扣库存、发货、状态推进和任何可重复执行的副作用。

规则：重试必须与幂等配套；使用业务唯一键、幂等记录或状态机防止重复副作用。

正例：去重标记与本地业务副作用在同一事务提交，用唯一约束处理并发重复；远程副作用使用下游幂等键并处理超时后的未知结果。

反例：对非幂等支付调用无条件重试三次。

例外：纯查询或明确幂等的操作可以重试，但仍需有限次数、退避和超时。

## TX-004 状态迁移与一致性方案

级别：MUST
适用：并发更新、跨服务状态流转和最终一致性流程。

规则：明确状态迁移的合法前置状态和并发控制（乐观锁、条件更新或行锁）；分布式事务不是默认选项，先评估最终一致性、可靠投递和补偿路径。

正例：使用 `UPDATE ... WHERE status = 'PENDING'` 检查受影响行数，失败进入补偿或人工处理。

反例：先查再改并假设不存在并发，或为了省事直接引入全局分布式事务。

例外：低并发后台任务可选择更简单的锁策略，但要说明并发假设和失败恢复。

# 测试

规则编号用于测试 Review 和回归计划；测试层级应与被测风险匹配。

## TEST-001 关键行为覆盖

级别：MUST
适用：核心业务、权限、状态流转和有副作用的 Service/Controller。

规则：根据被测行为覆盖成功、参数边界、资源不存在、异常、幂等和权限等相关路径；不要只追求覆盖率数字，也不要把每个简单 getter 强行扩展成复杂测试矩阵。

正例：订单创建覆盖库存不足、重复请求、未授权和状态冲突。

反例：只断言方法不抛异常，或只测试一条成功路径。

例外：纯转换器或无业务分支的简单方法可以采用更轻量的验证。

## TEST-002 单元与集成边界

级别：MUST
适用：包含数据库、消息、HTTP、序列化或事务行为的代码。

规则：单元测试隔离外部系统；集成测试验证真实序列化、事务、SQL 和关键中间件行为，优先使用隔离容器或测试实例。

正例：Service 单测 Mock 外部客户端，关键 SQL 和事务另用 Testcontainers 验证。

反例：所有测试都 Mock，导致 SQL 映射或事务回滚从未被验证。

例外：外部系统不可用时可以使用契约 Mock，但必须保留协议和失败响应覆盖。

## TEST-003 测试数据独立性

级别：MUST
适用：数据库、缓存、消息和并行执行的测试。

规则：测试数据独立、可重复、可清理；禁止依赖开发机共享状态、固定执行顺序或其他测试产生的数据。

正例：每个测试创建唯一数据并在事务/fixture 清理，显式准备消息和缓存状态。

反例：依赖本地已有用户、固定自增 ID 或“先运行测试 A 再运行测试 B”。

例外：只读静态 fixture 可以共享，但不得被测试修改。

## TEST-004 可靠性专项测试

级别：SHOULD
适用：并发、超时、重试、缓存失效、消息重复和外部依赖失败。

规则：对可靠性行为增加专项测试，并验证取消、超时、重复执行和恢复路径，而非只验证正常返回。

正例：模拟下游超时和重复消息，断言有限重试、幂等结果和最终状态。

反例：只 Mock 一次成功响应，却宣称覆盖了重试和消息可靠性。

例外：低风险纯查询可以通过契约测试或监控验证替代完整故障注入，但要说明理由。

## TEST-005 断言质量与可诊断性

级别：SHOULD
适用：JUnit、Mockito、集成测试和持续集成测试套件。

规则：断言业务结果、状态和关键交互，不用过度脆弱的实现细节断言替代行为；失败信息应能定位输入和原因。

正例：断言错误码、状态迁移和幂等结果，并在参数化测试中标注场景名称。

反例：只断言 `verifyNoMoreInteractions`，或把完整对象字符串作为唯一断言。

例外：安全敏感的调用次数、事务边界和审计事件可以作为额外交互断言。

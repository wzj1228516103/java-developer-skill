# Redis 与缓存

规则编号用于缓存 Review、回归验证和故障复盘；具体 TTL、序列化和容量参数以项目环境为准。

## CACHE-001 Key 与生命周期

级别：MUST
适用：Redis Key 设计、缓存写入和缓存清理。

规则：Key 包含项目、模块、业务和标识，格式服从项目约定；所有写入设置 TTL，除非明确是持久数据。

正例：`app:order:detail:{orderId}` 配置明确 TTL，并在变更时按同一格式失效。

反例：使用无命名空间的短 Key，或写入永不过期的业务缓存。

例外：明确作为持久数据使用的 Redis 结构必须有容量、备份和清理策略。

## CACHE-002 缓存一致性与权限

级别：BLOCKER
适用：缓存与数据库共同保存业务状态、权限或租户数据。

规则：通常在数据库提交后失效缓存，处理删除失败和并发旧值回填；仅调整先后顺序不保证强一致。缓存 Key 与查询都需隔离租户和用户权限，授权缓存明确撤销/过期策略，不能仅凭命中即放行。

正例：提交后删除并提供失败重试或补偿；权限使用可信授权上下文，明确缓存过期、撤销与允许的陈旧窗口。

反例：用户命中缓存就直接放行，或先删缓存再写数据库导致旧值回填。

例外：明确允许短暂最终一致的展示数据可以放宽，但要说明窗口和修复方式。

## CACHE-003 穿透、击穿与容量风险

级别：MUST
适用：高频查询、热点 Key、空结果和大对象缓存。

规则：设计缓存穿透、击穿、雪崩、大 Key 和热 Key 的处理；限制结果大小和批量范围，避免缓存故障放大数据库压力。

正例：对不存在对象使用短 TTL 空值或布隆过滤器，对热点 Key 使用互斥重建和随机 TTL。

反例：所有 Key 使用同一过期时间，或把无限列表和大对象直接放入缓存。

例外：低流量内部工具可以采用简单策略，但要确认流量和数据规模边界。

## CACHE-004 分布式锁生命周期

级别：BLOCKER
适用：跨实例互斥、缓存重建和定时任务抢占。

规则：锁有唯一 Key、持有者 token 和过期时间；释放必须原子地校验 token 并删除。租约过期、暂停或续期失败后旧持有者仍可能继续写，关键写操作另用版本/条件更新或 fencing token 防止失效持有者写入。

正例：Lua 原子校验并释放锁，写入端校验版本；设置持有时限并明确续期失败后的停止或拒写策略。

反例：任何实例都可删除锁，或业务异常后永远不释放锁。

例外：单实例内存锁不能宣称提供跨实例互斥，除非部署拓扑明确只有一个执行者。

## CACHE-005 序列化与版本兼容

级别：SHOULD
适用：缓存对象、空值缓存和跨版本发布。

规则：序列化格式、版本兼容和空值缓存时长写入项目约定；发布期间应兼容旧值或提供失效策略。

正例：缓存 DTO 带版本字段，读取失败时安全失效并回源。

反例：直接序列化内部 Entity，改字段后让所有旧缓存反序列化失败。

例外：短 TTL 且可安全回源的临时缓存可以采用简单兼容策略。
